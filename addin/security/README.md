# 情報漏洩対策集（Excelアドイン）

Excelの作業ウィンドウで「対策を見る › 事例 › 点検する › 可視化」を行うアドインです。「対策を見る」では、原因・対策・点検方法を縦に並べたアコーディオン（開閉式）で表示します。**データの保存先はExcelのブック**です。公開先は `https://ymatsuda-cmyk.github.io/tools/addin/security/` です。

## 配置するファイル

公開先フォルダ `tools/addin/security/` に、次のファイルをそのまま置きます。

```
tools/addin/security/
├─ manifest_security.xml   アドインの定義（Excelに読み込ませる。共有ランタイム設定つき）
├─ taskpane.html           アドインの画面（アプリ本体）
├─ cases.html              事例の表示画面（「事例」タブに埋め込まれる）  ← 追加
├─ cases-feed.json         事例の配信データ（「情報取得」が読む。自動更新される） ← 追加
├─ assets/                 リボン用アイコン
├─ automation/             事例の自動更新（GitHub Actionsで使う）           ← 追加
│  ├─ fetch_cases.py
│  └─ sources.json
└─ gas/                    元記事の取得・整理の中継（GoogleのApps Scriptに貼る。公開先には置かない） ← 追加
   ├─ Code.gs
   └─ appsscript.json
```

リポジトリの `.github/workflows/` には `github-workflows/fetch-cases.yml` を置きます（下の「事例の自動更新」参照）。以前のバージョンで置いた `taskpane.js` / `taskpane.css` は使わなくなったので、削除してかまいません。

`taskpane.html` と `cases.html` と `cases-feed.json` は**同じフォルダ**に置いてください（相対パスで読み合います）。

## 事例（新機能）

- **事例メニュー**：「事例」タブを開くと、事例ファイル（`cases.html`）がそのまま表示されます。上部の原因タイプ別の内訳バー、左の一覧（検索・時期・件数順・重要のみ）、右の詳細（発生日〜導入業者としての対策の7項目）の構成は、これまでの事例ファイルと同じです。
- **情報取得ボタン**：「事例」タブ上部の「情報取得」を押すと、最新の事例を `cases-feed.json` から取り込みます。
  - すでにある事例（IDまたは元記事のURLが同じもの）は追加しません。新着だけが追加されます。
  - Excelで直した内容は上書きしません。既存の事例の空欄だけを補います。
- **Excelに蓄積し、Excelから読み込む**：事例は、ブックの **「漏洩事例」シート**（表）に1行1事例で蓄積されます。「事例」タブを開くたびに、このシートから読み込みます。
  - シート上で企業名や原因タイプを直したり、行を足したりしても、「事例」タブに反映されます（「Excelから再読み込み」でも反映）。
  - 詳細列（発生日〜導入業者としての対策）に文章を入れると、7項目の詳細が表示されます。1行ごとの箇条書きは「・」で始めると箇条書きになります。HTMLで書いた場合は、安全でないタグ（script など）が取り除かれて表示されます。
  - 見出し行（1行目）の名前と列の順番は変えないでください。列の追加はできません（作り直し時に消えます）。
  - 「漏洩_」で始まるシートと違い、「漏洩事例」シートは作り直されません（事例の保管場所です）。
- 最初にアドインで「情報取得」を押すと、これまで整理した72件（うち7項目まで整理済みが9件）が「漏洩事例」シートに入ります。

## 事例の自動更新（GitHub Actions）

ブラウザのアドインから他社サイトを直接読むことは、アクセス制限（CORS）のためできません。そこで、**GitHub Actionsが毎日サーバー側で新着を集めて `cases-feed.json` を更新**し、アドインの「情報取得」はそのファイルを読みます（同じ公開先のファイルなので制限がかかりません）。

1. `github-workflows/fetch-cases.yml` を、リポジトリの `.github/workflows/fetch-cases.yml` として置く
2. `automation/` を `addin/security/automation/` に置く（上の構成のとおり）
3. リポジトリの Settings › Actions › General › Workflow permissions を **Read and write permissions** にする
4. Actions タブで「情報漏洩事例フィードの更新」を選び、**Run workflow** で一度実行して、ログに「新規 n 件」と出ることを確認する
5. 以後、毎日 07:00（日本時間）に自動実行されます

- 取得元は `automation/sources.json` で指定します。初期設定は「サイバーセキュリティ.com」のニュース一覧です。RSSを出している情報源は `type: "rss"` で追加できます。
- 保存するのは、タイトル・公表日・元記事URL・取得元だけです（記事本文は保存しません）。企業名・件数・原因タイプはタイトルからの簡易判定なので、間違いはExcelの「漏洩事例」シートで直してください。
- **注意**：取得元サイトの利用規約と、自動取得の可否を確認してから有効にしてください（1日1回・1秒間隔で取得する設定です）。
- 手元で確認するには `python automation/fetch_cases.py --feed cases-feed.json --sources automation/sources.json --dry-run` を実行します（新着の一覧が出るだけで、ファイルは変更しません）。
- 公開側に反映されないときは、Actionsの最後の手順（Pages再公開）のログを確認するか、Settings › Pages でビルドを再実行してください。

## 元記事からの詳細の整理

「元記事を開く」だけだった事例（一覧情報のみの63件、および今後の新着）について、元記事の内容から**発生日・概要・発覚の経緯・リスク・原因・対処・導入業者としての対策**を整理できます。ブラウザのアドインから他社サイトの記事を直接読むことはできない（CORS）ため、**サーバー側で記事を取得する中継**が必要です。2通りあり、併用もできます。

| | A. GAS（Google Apps Script）を中継にする | B. GitHub Actionsで毎日自動 |
|---|---|---|
| いつ整理するか | アドインで **「情報取得」を押したとき**（その場で） | 毎日 07:00（日本時間）に最大8件 |
| 設定するもの | GASを1つ作成・公開し、アドインにURLとトークンを入力 | `.github/workflows` にファイルを置き、Secretsにキーを登録 |
| 向いている場合 | 押したらすぐ詳細が欲しい | 放っておいても溜まってほしい |

### A. GASを中継にする（「情報取得」で元記事から整理）

`gas/Code.gs` が、アドインに代わって元記事を取得し、7項目に整理して返します。

**設定の手順**

1. <https://script.google.com> で「新しいプロジェクト」を作り、`gas/Code.gs` の内容を貼り付ける
2. プロジェクトの設定 › スクリプト プロパティ に次を登録する
   - `TOKEN`（必須）：12文字以上の長いランダムな文字列。アドインにも同じ値を入れます
   - `ANTHROPIC_API_KEY`（任意）：Claude APIのキー。あると記事の本文を読んで7項目を整理します。ないと、7項目に分けず、サイトの記事本文をそのまま返します
   - `ALLOWED_HOSTS`（任意）：取得を許可するサイト（カンマ区切り）。既定は `cybersecurity-jp.com`
   - `DAILY_LIMIT`（任意）：1日に処理できる記事数の上限。既定は200
   - `ANTHROPIC_MODEL`（任意）：使うモデル。既定は `claude-sonnet-5-5`
3. デプロイ › 新しいデプロイ › 種類「ウェブアプリ」 › **次のユーザーとして実行：自分** ／ **アクセスできるユーザー：全員** › デプロイ（初回は権限の承認が必要です）
4. 表示された **ウェブアプリのURL（…/exec）** をコピーする
5. アドインの「データ管理 › 元記事の取得（GAS）」に、URLとトークンを入力して「保存」 › 「接続テスト」で確認する

設定すると、「事例」タブの **「情報取得」** が、フィードの取り込みに続けて、元記事の整理（1回に3〜20件。設定で変更）まで行います。「元記事から詳細を整理」ボタンで、整理だけを実行することもできます。コードを直したときは、デプロイ › デプロイを管理 › 新しいバージョンで更新してください。

**安全のための仕組み**

- 呼び出しにはトークンが必要です（トークンがないと全て拒否）。トークンはURLではなく通信の本文で送ります。
- 取得できるのは、https かつ `ALLOWED_HOSTS` に書いたサイトだけです。IPアドレス・ローカル・許可外へのリダイレクトは拒否します（任意のサイトを読ませる中継にならないようにするため）。
- 1日の上限（`DAILY_LIMIT`）を超えると止まります。トークンが漏れても、Claude APIの利用はこの上限までです。
- URLとトークンは、**このPCのアドインの保存領域だけ**に保存します。ブックには保存しないので、ブックを共有しても渡りません。トークンが漏れたら、`TOKEN` を変更してアドインの設定も更新してください。
- 公開設定を「全員」にできるのは、Googleアカウントの管理者がそれを許可している場合だけです。社内のGoogle Workspaceで選べない場合は、個人のGoogleアカウントで作るか、Bの方法を使ってください。
- 取得元サイトの利用規約に沿った範囲でお使いください。

### B. GitHub Actionsで毎日自動

- リポジトリの Settings › Secrets and variables › Actions に **`ANTHROPIC_API_KEY`** を登録します（任意。ないと本文冒頭の紹介（1段落）だけ。公開フィードには本文を載せないため）。
- 1回の実行で最大8件、新しい記事から順に整理して `cases-feed.json` に入れます（`--enrich-limit` で変更、`0` で無効）。「情報取得」を押すと、そこまでに整理された詳細がExcelの空欄に補われます。
- 急ぐときは、Actionsから「Run workflow」を繰り返し実行してください。失敗した記事は翌日以降に再試行します。

### AIが使えないときは、サイトの記載をそのまま本文として表示

`ANTHROPIC_API_KEY` が未設定、またはAIの整理に失敗したときは、**7項目（発生日・概要・発覚の経緯・リスク・原因・対処・導入業者としての対策）に無理に分けず、サイトの記事本文をそのまま文章で取り込みます。**

- GAS（A）が、記事の冒頭の段落から関連記事の手前までを取り出し、「漏洩事例」シートの **「記事本文」列** に入れます（見出しは「■ 見出し」の行で残ります）。「整理方法」列は `本文` になります。次のものは取り込まず（表示でも除きます）、本文だけを残します：メニュー、広告・案内（イベント・セミナーの告知、メルマガ登録・書籍プレゼント、「詳細はこちら→」など）、画像のクレジット（「画像：〇〇より引用」）、記事の目次、「*」「->」「■」だけの行や中身のない見出し、関連記事。
- 事例タブでは、7項目のタブではなく、本文がそのまま表示されます。一覧では、本文を取り込んだ事例に白抜きの点が付きます（7項目まで整理済みの事例は青い点）。
- **すでにExcelに保存してある本文も、「情報取得」を押すと整えて書き戻します**（メッセージに「保存済みの本文 n件から、広告・案内などを除きました」と出ます）。「事例」タブを開いたときも、画面に出る内容は整えて表示します。
- **古い画面が動いていないかの確認**：事例の画面上部の「全N件…」の行の末尾に「表示 v9」、「データ管理」の下部に「画面のバージョン：2026-10-20 r8」と出ます。出ない場合は、`taskpane.html` / `cases.html` が古いままです。公開先のファイルを差し替えたあと、作業ウィンドウを閉じて開き直すか、アドインを削除して追加し直す／Officeのキャッシュを削除してください。
- 取り除く内容は、広告・案内と思われる決まった文言（メルマガ、無料会員登録、プレゼント、「詳細はこちら」など）で判定しています。「会員登録時に入力した…」のような通常の文は消えません。取り除かれていない案内文があれば、その文言を教えてください（追加します）。表示でも同じ除去をするので、すでにExcelに入っている本文にも効きます。
- 記事ページの紹介文（meta description）は、サイト側で文の途中までしか出していないことがあるため使いません（本文の冒頭の段落から取ります）。
- 「情報取得」後のメッセージで、何が起きたかが分かります。例：`元記事から 3件を取得（AIで整理 0件、サイトの本文のまま 3件［GASに ANTHROPIC_API_KEY が未設定です］）`。
- 後からAIが使えるようになったとき、本文のみの事例は7項目の整理に置き換わります。このとき、サイトの本文も残り、詳細に **「サイトの記載」タブ** が付くので、AIの整理を元の文章と見比べられます。旧版が入れた途中で切れた紹介文も同じ扱いです（手で書いた概要は置き換えません）。
- 一度失敗した記事・本文のみになった記事は、7日間は再試行しません。キーを設定した直後などは、「データ管理 › 元記事の取得（GAS）」の「失敗・紹介文のみの記事を再試行の対象に戻す」を押してから「情報取得」してください（設定を「保存」したときも、記録はリセットされます）。
- **GitHub Actions（B）では、記事本文は保存しません。** `cases-feed.json` はGitHub Pagesで誰でも読める公開ファイルなので、他社サイトの本文を載せると再公開になってしまうためです。AIが使えないときは、本文冒頭の紹介（1段落）だけを入れます。本文を取り込みたい場合は、Aの方法を使ってください（本文は、あなたのExcelのブックにだけ入ります）。
- **取得元サイトの利用規約・二次利用の案内を、必ず確認してください。** 記事本文の著作権は元サイトにあります。本文をそのまま取り込む機能は、社内で参照するための利用にとどめてください（ブックを社外に共有・公開しない）。この確認は、私の側ではできていません（サイトの二次利用の案内を読めませんでした）。

### 共通

- **整理の内容**：記事に書かれていないことは「記事に記載なし」になり、本文は写さず要約します。「導入業者としての対策」だけは、事例から導いた提案として書かれます。
- **確認のお願い**：AIが整理した詳細には、事例の画面に「元記事で確認してください」と表示され、「漏洩事例」シートの「整理方法」列に `AI` と入ります。誤りや抜けがあるかもしれないので、重要な事例は元記事で確認し、シート上で直してください。直した内容や、手で書いた項目は、以後の取得で上書きされません（空欄だけが補われます）。
- **費用**：AIで整理する記事1件につき、Claude APIを1回呼びます。
- **保存するもの**：記事本文は保存しません。保存するのは、整理した要約・元記事のURL・取得元です。
- 手元で確認するには `python automation/fetch_cases.py --feed cases-feed.json --sources automation/sources.json --dry-run` を実行します（Bの整理対象の件数が出るだけで、ファイルは変更せず、APIも呼びません）。

## 一覧からTeamsへコピー

事例タブの左の一覧で、事例の行を選んで、そのままTeamsに貼り付けて共有できます。行の選び方は、Windowsのエクスプローラーと同じです。

| 操作 | 動き |
|---|---|
| クリック | 詳細を表示する（その1件だけが選択された状態になる） |
| Ctrl（Macは ⌘）＋クリック | 選択に追加／選択から外す（詳細表示は変わらない） |
| Shift＋クリック | 基準にした行から、クリックした行までを範囲選択 |
| Ctrl＋Shift＋クリック | いまの選択を残したまま、範囲を追加 |
| Ctrl＋A（一覧の上で） | 表示中の行をすべて選択 |
| Esc | 選択を解除 |
| Ctrl＋C | 選択した事例を「Teams用」にコピー |

- 選択した行は、青くハイライトされます。選択の操作では、一覧は作り直されないので、スクロール位置は動きません。
- 一覧の上の「表示中を全て選択」「選択解除」のボタンでも、同じ操作ができます。絞り込み中は、表示されている行だけが対象です。
- 「Teams用にコピー」（または Ctrl＋C）で、コピーされます。形式は「箇条書き」か「表」を選べます。Teamsのメッセージ欄に貼り付けると、太字の見出しとリンク付きで貼り付きます（表は、Teamsの表として貼り付きます）。
- 事例の詳細画面の「この事例をTeams用にコピー」で、その1件だけをコピーすることもできます。
- タッチ操作など、Ctrl・Shiftキーを使えない環境では、複数行は選べません（1件ずつ、詳細画面のボタンでコピーしてください）。
- コピーされる内容：日付（発生日基準。年が違うときは年つき）・企業（サービス）・規模・種別・概要・元記事のURL。選んだ事例は、一覧と同じ並び（新しい順）になります。概要は、AIで整理した概要、なければ取り込んだ記事本文の最初の段落、それもなければ一覧用の概要の順に使います（記事本文の全文は入れません）。
- お使いの環境でコピーが許可されていない場合は、選んだ内容の文章が欄に表示されるので、選択してコピーしてください。
- 記事の内容を社外に共有するときは、取得元サイトの利用規約を確認してください。

## 記事本文の取り込み（情報取得）

「情報取得」を押すと、新着の事例がExcelの「漏洩事例」シートに入り、**GASを設定していれば、各事例の記事本文が「記事本文」列に取り込まれます**（「元記事を開いて確認」する必要がないようにするためです）。GASを設定していない場合、本文は取り込まれません。

- 「データ管理 › 元記事の取得（GAS）」で、1回に取り込む件数を選びます。**初期値は「全件」（最大200件）**です。AIで整理する場合は、件数に応じてClaude APIの費用がかかります。
- 取り込み中は、「N / 全体」の進み具合が表示されます。**途中でも「中止」を押せます**。10件ごとにExcelへ保存するので、中止したり閉じたりしても、そこまでの分は残ります。
- 件数を絞った場合や中止した場合は、「残り N件（もう一度押すと続きを取り込みます）」と表示されます。もう一度「情報取得」（または「本文を取り込む」）を押すと、続きから取り込みます（取り込み済みは再取得しません）。
- 本文を取り込んだ事例は、事例タブで本文がそのまま表示されます（一覧では白抜きの点）。本文が未取得の事例には、「記事本文は、まだ取り込まれていません」と表示されます。

## 外部攻撃の点検項目（追加）

「外部攻撃（脆弱性悪用）」の点検方法を、4項目から14項目に増やしました。

| 追加・修正 | 内容 | 頻度 |
|---|---|---|
| 修正（ext-3） | **すべての**管理者アカウントに多要素認証が設定されているか | 四半期 |
| 修正（ext-4） | 認証ログに不審なログイン**成功**（海外IP・深夜・未使用アカウントなど）がないか | 月次 |
| 追加 | ログイン失敗が急増したときにアラートが出る設定か | 四半期 |
| 追加 | 初期パスワード・共通パスワードが残っていないか | 四半期 |
| 追加 | 外部公開のログイン画面にアカウントロック・試行回数制限があるか | 四半期 |
| 追加 | VPN・リモート接続の**全ユーザー**に多要素認証があるか | 四半期 |
| 追加 | 外部公開Webアプリの脆弱性診断を1年以内に実施し、指摘が残っていないか | 年次 |
| 追加 | 保守期限切れのOS・機器・ミドルウェアが外部公開されていないか | 半期 |
| 追加 | IPA・JPCERT/CCの緊急注意喚起に期限内に対応した記録があるか | 随時（注意喚起時） |
| 追加 | ソースコード・設定ファイルにパスワード・APIキーが含まれていないか | 変更時 |
| 追加 | VPN・FW・認証ログが一定期間（例：1年）保管されているか | 半期 |
| 追加 | 侵入時の切り離し・ログ保全手順が文書化されているか | 年次 |

あわせて、対策（予防・検知）の文言と、頻度の選択肢「随時（注意喚起時）」も追加しています。

- すでにExcelに保存されているデータは、**アドインを開いたときに自動で移行**されます（1回だけ）。点検結果は消えません。更新履歴にも追記されます。
- ext-3・ext-4は文言を変えたので、すでに記録した結果がある場合は、新しい基準で見直してください。

## 保存の仕組み

| 何を | どこに | いつ |
|---|---|---|
| 対策・取引先・対象判定・点検結果 | ブックの非表示シート `_data`（JSON） | 画面で変更するたびに自動（約1秒後） |
| 事例 | ブックの「漏洩事例」シート（表） | 「情報取得」を押したとき。以後はシート上の編集がそのまま正になる |
| 見やすい表（`漏洩_サマリ`／`漏洩_対策一覧`／`漏洩_取引先`／`漏洩_対象判定`／`漏洩_点検結果`／`漏洩_要対応`） | 「漏洩_」で始まる6枚のシート（出力専用） | 「データ管理 › Excelの表を更新」を押したとき（任意で変更の12秒後に自動） |

- 入力は画面（作業ウィンドウ）で行います。「漏洩_」シートは**出力専用**で、アドインが作り直すため、Excel側で編集しても反映されません。自分用の計算は別のシートに書いてください。
- デスクトップ版Excelでは、通常どおりブックを保存（Ctrl+S）してください。Excel on the web は自動保存です。
- ブックごとにデータは独立します。

## ブックを開いたときに自動で開く（共有ランタイム）

マニフェストには共有ランタイム（`SharedRuntime 1.1`、`lifetime="long"`）が設定されています。ブックを開いたときに自動で画面を開くには、ブックごとに1回、「データ管理 › Excelへの保存」の **「ブックを開いたときに、自動でこの画面を開く」** にチェックを入れます。共有ランタイムに対応していない環境では、マニフェストの追加時にエラーになることがあります。

## Excelへの追加（サイドロード）

- **Excel on the web**：挿入 › アドイン › 個人用アドインのアップロード › `manifest_security.xml` を選択
- **Windows版Excel**：manifest_security.xml を置いたフォルダを共有フォルダにし、ファイル › オプション › トラストセンター › 信頼できるアドインカタログ に共有パスを登録 › Excelを再起動 › 挿入 › 個人用アドイン › 共有フォルダー
- **Mac版Excel**：`~/Library/Containers/com.microsoft.Excel/Data/Documents/wef/` に manifest_security.xml をコピー › Excelを再起動 › 挿入 › 個人用アドイン
- **社内配布**：Microsoft 365 管理センター › 統合アプリ からマニフェストを展開

`manifest_security.xml` は変更していません（今回の更新ではマニフェストの修正は不要です）。

## うまく動かないとき

- エラーには「どの段階で失敗したか」が表示されます（例：「事例の書き込みでエラー：…」）。その文言をそのまま共有してください。
- 「cases-feed.json を取得できませんでした（HTTP 404）」と出た場合は、`cases-feed.json` が `taskpane.html` と同じフォルダに置かれていません。
- 「『漏洩事例』シートの1行目の見出しが見つかりません」と出た場合は、1行目の見出しを書き換えていないか確認してください。
- 「一部の書式は適用できませんでした：…」と出た場合、データは保存されています。表・色分け・グラフなど、Excelの版によって使えない装飾だけが省かれています。
- 「Excelの保存データを読み込めていないため、自動保存を止めています」と出た場合は、保存データが壊れているか読めない状態です。JSONバックアップから戻すか、「今すぐExcelに保存」で現在の画面の内容に上書きしてください。
- 更新したファイルを置き直したあとも古い画面が出る場合は、作業ウィンドウを閉じて開き直してください。それでも変わらない場合は、アドインを削除して追加し直すか、Officeのキャッシュを削除します（Windows：`%LOCALAPPDATA%\Microsoft\Office\16.0\Wef\`、Mac：`~/Library/Containers/com.microsoft.Excel/Data/Library/Caches/`）。
