# ステップ数集計アドイン

フォルダに取引先名を割り当て、取引先 › フォルダ › 拡張子の3階層でステップ数をドリルダウン集計する Excel 作業ウィンドウアドインです。集計はすべてアドイン側のメモリで行い、シートには「割当」「除外」「出力結果」だけを置きます。

## ファイル構成

```
step-count-addin/
  manifest.xml        アドインのマニフェスト
  package.json        ローカル配信用のスクリプト
  src/
    taskpane.html     作業ウィンドウのマークアップ
    taskpane.css      スタイル
    taskpane.js       読み込み・割当解決・集計・出力
```

## ブックの準備

シート名は `taskpane.js` 冒頭の `SHEET` で変えられます。

### `データ`（必須・1行目はヘッダー）

| A: パス | B: 拡張子 | C: 総ステップ | D: 実ステップ |
|---|---|---|---|
| `10.1.1.3\winntdir\delphi5\Amp\PROC.pas` | pas | 3989 | 2766 |

- 区切りは `\` でも `/` でも構いません。先頭の `\\` は自動で落とします。
- B列が空の場合はファイル名の拡張子を使います。
- C・D列は数値でも `1,234` のような文字列でも読めます。

### `割当`・`除外`（無ければ初回起動時に自動作成）

| A: フォルダパス | B: 取引先名 / メモ |
|---|---|
| `10.1.1.3\winntdir\delphi5\Amp` | ライターム商事 |
| `10.1.1.3\winntdir\delphi5\Amp\旧バージョン` | 旧版・バックアップ |

いずれも**最長一致した祖先が勝つ**方式です。`Amp` に取引先を付けた後で `Amp\SetSUM` に別の取引先を付けると、`SetSUM` 配下だけが後者になります。除外も同じ規則で、`旧バージョン` を1行入れれば配下 20 世代すべてが除外扱いになります。

## 起動手順

```
cd step-count-addin
npm run cert          # 初回のみ。localhost の開発証明書を入れる
npm start             # https://localhost:3000 で src/ を配信（Mac は npm run start:mac）
```

別のターミナルでサイドロードします。

- **Windows デスクトップ**: 共有フォルダを1つ作り `manifest.xml` を置く → Excel の「ファイル ＞ オプション ＞ トラスト センター ＞ 信頼できるアドイン カタログ」にそのパスを登録 → Excel 再起動 → 「挿入 ＞ 個人用アドイン ＞ 共有フォルダー」から選択。
- **Excel for Web**: 「挿入 ＞ Office アドイン ＞ マイ アドイン ＞ カスタム アドインのアップロード」で `manifest.xml` を指定。

リボンに「ステップ数集計」タブが出ます。

## 使い方

**割当タブ** — フォルダツリーが総ステップ数の降順で並びます。チェックボックスは常に操作できます。フォルダをチェックすると配下のフォルダも自動でチェックされます（サブツリーをまとめて選ぶ操作です）。取引先名を入力して「割り当て」を押すと、チェックした中でいちばん上位のフォルダにだけ割当が書き込まれます（配下は継承で自動的に含まれるため）。

割当済み・継承済みのフォルダも選択できます。「解除」の動作はフォルダの状態によって変わります。

- 個別に割り当てたフォルダを選んだ場合 → その割当を削除します（親がなければ未割当に戻ります）。
- 「継承 ○○」と表示されているフォルダを選んだ場合 → そのフォルダだけ継承を断ち切り、`（解除）`という印を`割当`シートに書き込みます。ツリーには「解除済み」バッジが付き、以後そのフォルダ（と配下）は親の取引先を継承しません。もう一度同じフォルダを選んで「解除」を押すと、この印を消して継承を元に戻せます。
- 割当も継承もないフォルダを選んだ場合 → 何も変わらず、その旨を知らせます。

「除外」ボタンは同じ選択に対して除外フラグを立てます。`旧バージョン` `back1205` `v101` `old` `SAVE` `backup` あたりを潰していく想定です。

**集計タブ** — 内訳は「フォルダ」（取引先 › フォルダ › 拡張子の3階層）と「拡張子」（取引先 › 拡張子の2階層）の2つから選べます。「フォルダ」欄には、割当（または解除）が行われたフォルダそのものの名前が出ます。例えば `TouchPanel` に割り当てて、その配下の `20200306解像度大BACKUP` にもファイルがある場合、両方とも「フォルダ」欄は `TouchPanel` にまとまります（配下の孫フォルダ名ではなく、割当地点の名前で集約されます）。

各行には「ファイル数 / ステップ数」の順で数値が並びます。行の操作は次の2種類です。

- **フォルダ名をクリック** → その配下の該当ファイル一覧を表示します（相対パス・ファイル名・拡張子・ステップ数）。
- **▶/▼（左端の三角）をクリック** → 拡張子ごとの内訳をその場で開閉します（一覧を見ずに構成比だけ確認したいとき用）。

取引先行・拡張子の行、および横棒グラフ自体をクリックした場合も、その行のすぐ下にファイル一覧がインラインで展開されます（別画面には切り替わりません）。もう一度クリックすると閉じます。一覧が長い場合は内側だけスクロールします。

「除外行を外す」を切れば旧版を含めた総量が見えます。除外した分は「除外ステップ」カードに出ます。

**シートに出力** — 現在の表示条件で `集計_取引先` `集計_拡張子` `集計_クロス` の3シートを作り直します。`集計_クロス` は取引先・フォルダ・拡張子の平坦形式なので、そのままピボットテーブルの元データに使えます。

## 実装メモ

- 読み込みは `getUsedRange()` の行数を測ってから CHUNK 行ずつ読み、以降はすべて JS 側で処理します。行ごとに `context.sync()` を呼ぶ実装は数千行で分単位になるため避けています。
- 割当・除外の解決は `lookup()` でフォルダ階層を末尾から遡り、最初に一致した祖先を採用します。
- ツリーのチェックボックスは常に操作でき、チェックすると `setSubtreeChecked()` が配下すべてに伝播します。書き込み時は `topmostPicks()` で祖先が選択されている経路を除外し、最上位のフォルダにだけ割当・除外・解除操作を適用します。
- 継承の解除は `UNASSIGN_MARK`（`（解除）`という文字列）を `割当` シートにそのフォルダのキーとして書き込むことで実現しています。`lookup()` は他の割当と同じように最長一致でこの印を見つけ、`buildModel()` と `markTree()` の両方でこの印を「取引先なし」として扱い、祖先からの継承をそこで打ち切ります。同じフォルダにもう一度「解除」を押すと印が消え、継承が復元されます（トグル動作）。
- `CARRY_UNC_ROOT`（`taskpane.js` 上部）は、`\\host\share\...` 行の後に続く `\Exe\...` のような相対パス行に直前のルートを引き継ぐスイッチです。正規化済みのデータを前提に既定 `false` にしています。
- 集計の「フォルダ」内訳は `groupOf()` が割当（または解除）が実際に行われたフォルダ自身の名前を返します（`f.folder[f.assignDepth - 1]`）。そのフォルダの配下に何階層サブフォルダがあっても、同じ名前に集約されます。
- グラフ・フォルダ名・拡張子行のクリックは `state.openFiles`（開いているバケットの集合）を切り替えて `renderSummary()` を呼び直すだけです。開いているバケットは `inlineFiles()` がその場で `filesForBucket()` を呼んで一覧をその行の直下に差し込みます。ファイル配列を事前に保持しないので、内訳の軸を増やしても実装がシンプルなままです。フォルダ行だけは名前クリックとは別に、左端の▶/▼ボタンで拡張子内訳の開閉ができるよう、クリック対象を分けています（`data-l2` は三角ボタン、`data-vendor`/`data-group`/`data-ext` は名前のテキストとグラフ）。取引先名・フォルダ名・拡張子名は3つの別属性に分けて持たせています。1つの属性にNUL文字などの区切り文字で詰め込むと、HTMLの仕様上ブラウザが属性値中のNUL文字を強制的に置換文字に書き換えてしまい、値が壊れて一覧が空になる不具合があったためです。
- 出力シートは毎回使用範囲をクリアして書き直します。ここに手で列を足しても消えるので、加工は別シートで行ってください。

## 大きいシートの読み書き

Excel for Web は1回の `context.sync()` で扱えるデータ量に上限があり、1万行規模のシートを一括で読むと `GeneralException: 内部エラーが発生しました。` になります。そのため読み込み・書き込みはいずれも `CHUNK`（既定 2000 行、`taskpane.js` 上部）ずつに分割しています。

- 読み込み: `getUsedRange()` で行数だけ取得 → 2000 行ずつ `getRangeByIndexes()` で読む。進捗はステータス行に出ます。
- 書き込み: `割当` `除外` と出力3シートも同じ単位で分割。クリアも使用範囲の実寸だけを対象にします。

さらに大きいブックで落ちる場合は `CHUNK` を 1000 や 500 に下げてください。逆にデスクトップ版だけで使うなら 5000 程度まで上げると速くなります。

## うまく動かないとき

| 症状 | 対処 |
|---|---|
| `GeneralException: 内部エラーが発生しました。` | `CHUNK` を 1000 に下げる。ステータス行の進捗が途中で止まった行数から、どのシートで落ちたか切り分けられます。 |
| `シート「データ」が見つかりません` | シート名を確認、または `taskpane.js` の `SHEET.data` を実際の名前に変える。 |
| ツリーが空 | `データ`シートのA列にパスが入っているか、1行目がヘッダーになっているかを確認。 |
| 集計が0 | C・D列（総ステップ・実ステップ）が数値として入っているかを確認。 |
| ブラウザで作業ウィンドウが真っ白 | `https://localhost:3000/taskpane.html` を別タブで開き、証明書の警告を承認する。 |

エラーの詳細は F12 の Console にも出します。`describe()` が Office API の `debugInfo` を展開するので、どのステートメントで落ちたかが分かります。

## 拡張しやすい箇所

- ファイル一覧（グラフクリック時）にさらに絞り込み（拡張子ごとの色分け、ファイル名でのその場検索など）を足したい場合は `inlineFiles()` を拡張します。
- コメント率（総 − 実）を出したい場合は `aggregate()` で両方を集計し、行の表示に列を追加します。
- 取引先の並び順を売上順など任意にしたい場合は、`割当` シートに順序列を足して `state.vendors` のソートを差し替えます。
