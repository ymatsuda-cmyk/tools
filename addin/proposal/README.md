# 提案ナレッジ Officeアドイン

議事録の登録 → ROI試算 → 課題×解決案の提案 → 提案書用プロンプト出力、までをタスクペインから行うアドインです。
既存の「営業報告」アドインとは別アドインとして動作し、**既存のシート（営業報告・wbs・課題・顧客マスタ・体制・確度設定 等）は一切変更しません**。同じワークブックに新しいシートを追加するだけです。

## 画面構成（3タブ）

| タブ | 内容 |
|---|---|
| ①議事録入力 | 案件ID・課題カテゴリを指定して発言を記録。「AIで抽出してROI試算に反映」でAI連携エンドポイントを呼び出し、抽出結果をレビュー後にROI試算シートへ保存 |
| ②提案 | 案件のROI試算結果を課題カテゴリ単位でカード表示。ソリューションDBと突き合わせて解決策を表示。チェックした課題だけが③に渡る |
| ③プロンプト出力 | ②でチェックした課題から、生成プロンプト・顧客インプット・ROI数値・章立て骨子をブロックごとにコピーできる形で出力 |

案件IDは既存の「営業報告」シートのID列（顧客コード-通番、例: `KM-01`）と揃える前提です。入力欄はそのIDを候補（datalist）として表示します。

## 追加されるシート

### ROIマスタ（運用側が計算式を直接編集する場所）

| 列 | 内容 |
|---|---|
| 課題カテゴリ | 在庫管理／ロット管理／AI議事録 など |
| 項目ID | `stk_people` のような一意キー |
| 項目名 | 画面表示用の名称 |
| 区分 | 入力／出力 |
| 単位 | 人・時間・円・% など |
| デフォルト値 | 入力項目のみ。新規案件作成時の初期値 |
| 数式 | 出力項目のみ。**項目IDのトークン式**（例: `stk_people*stk_hours*stk_freq`） |
| 信頼度初期値 | 入力項目のみ |

初回起動時に在庫管理・ロット管理・AI議事録の3カテゴリをサンプルとして自動投入します。カテゴリの追加・項目の追加・数式の変更は、このシートを直接編集するだけで反映されます（アドインの再インストールは不要）。

### 議事録

案件ID・課題カテゴリ・発言者・発言テキスト・登録日時。①のタブから追記されます。

### ROI試算

案件ID・課題カテゴリ・項目ID・項目名・区分・値・単位・信頼度・選択（提案書に含めるかのチェック状態）・更新日時。

**「値」列の出力行はExcelの数式です。** ROIマスタの数式（項目IDのトークン式）を、同じ案件内の入力行を `INDEX`/`MATCH` で参照する数式に変換して書き込みます。計算ロジックはこのアドインのJavaScriptにもAIにも持たせず、Excelの数式評価だけに委ねています。マスタの数式を直せば、次に①で反映し直したときから新しい計算式が使われます（既存行は上書きしません。数式を直した場合は該当行を手動で消してから再反映してください）。

### ソリューションDB

課題カテゴリ・解決策名・概要。②の提案カードで課題と結びつけて表示します。

## AI連携（GAS Webhookサンプル同梱）

`gas/Code.gs` を Google Apps Script プロジェクトにコピーし、以下を行ってください。

1. スクリプトプロパティに `AI_API_KEY` を設定（APIキーはここにのみ置く。クライアント側のJS/HTMLには一切含めない）
2. 「Webアプリとして公開」→ アクセスできるユーザー：全員　でデプロイし、発行されたURLを控える
3. アドインの設定（タスクペイン右上の⚙）で、そのURLを「AI連携エンドポイント」に登録する

リクエスト・レスポンスの形式は `gas/Code.gs` 冒頭のコメントを参照してください。GASの制約上、レスポンスは `text/plain` で返し、クライアント側で `JSON.parse` しています（`application/json` で返すとpreflightで失敗することがあるため）。

将来的にストリーミング表示や高頻度アクセスが必要になった場合は、同じリクエスト/レスポンス形式のままサーバをCloudflare Workers等に差し替えれば、`app.js` 側の変更は不要です。

## デプロイ手順（GitHub Pages）

1. `manifest.xml` `index.html` `app.js` `style.css` `commands.html` `commands.js` `icons/` 一式を、既存の営業報告アドインと同じリポジトリの `tools/addin/roi-knowledge/` として配置
2. `icons/` は暫定的に営業報告アドインのアイコンを流用しています。実運用前に差し替えてください
3. `manifest.xml` をサイドロード、または Microsoft 365 管理センターから組織展開
4. Excelで対象ブックを開き、ホームタブの「提案ナレッジ」ボタンでタスクペインを表示

## デモモード

`index.html` をブラウザで直接開くと、Excelに接続せずデモバッジ表示で起動します（ROIマスタのサンプルカテゴリのみ確認可能。書き込み系の操作はシミュレーションのみで実際には保存されません）。

## 既知の制約・今後の調整ポイント

- ROI試算シートへの反映（①の「保存」）は、対象カテゴリの行がその案件にまだ無い場合にまとめて追加する方式です。ROIマスタの数式を後から変更した場合、既存の出力行の数式は自動更新されません（該当行を削除してから再度①で反映してください）。
- ②の「削減額」表示は、項目IDが `_saving` で終わる出力項目を自動的に主要指標として拾っています。カテゴリごとに主要指標が複数ある場合は、この判定ロジック（`loadProposal` 内）を調整してください。
- 数式は `INDEX`/`MATCH` を使った動的配列前提です。古いExcel（配列数式にCtrl+Shift+Enterが必要なバージョン）では別途対応が必要です。
