# addin/schedule — 期スケジュール（Excel「計画シート」連携）

カンバン（WBS）アドインのメニューから開くツールです。メニューのリンクで作業ウィンドウに `index.html` が開き、そこからポップアップ（`app.html`）を開きます。
ポップアップの変更は、ブックの `計画シート`／`計画マスタ` に書き込まれ、Excelの共同編集で他の人が変えた内容もポップアップに反映されます。

## ファイル
| ファイル | 役割 |
|---|---|
| `index.html` | ホスト。メニューのリンクで開く。Excelの読み書きを担当し、ポップアップを開いて中継する |
| `app.html` | スケジュール本体（ポップアップ）。`?excel=1` 付きで開くとExcel連携モード |
| `schedule-bridge.js` | ホスト側のコード（シートの読み書き、差分マージ、イベント監視） |
| `../common/menu.json` | 「スケジュール」を1行追加した版（`WBS` の次） |

## リポジトリへの置き方
1. `addin/schedule/` の4ファイルを、リポジトリの `addin/schedule/` に追加する。
2. `addin/common/menu.json` を、同梱の版に差し替える（差分は `schedule` の1項目と `updated` の日付だけ）。
3. GitHub Pages に反映されたら、Excelのカンバンのメニューに「スケジュール」が出る。

マニフェスト（`manifest._kanban.xml`）の変更は不要です。`ymatsuda-cmyk.github.io` は `AppDomains` に入っていて、ポップアップのURLも同じドメインだからです（ダイアログは、ホストと完全に同じドメインのページしか開けません）。
DialogApi 1.2（ホスト→ポップアップの送信に使う）はマニフェストに書かず、`index.html` で実行時に判定します。未対応のExcelでは、その旨を表示して開きません。

## 動き
- メニュー →「スケジュール」で `index.html` が開き、自動でポップアップを開く（環境によっては許可の確認が出る）。出ない場合は「ポップアップで開く」ボタン。
- 初回は、ブックに `計画シート` と `計画マスタ` を自動で作る。**既存のシート（wbs・体制・顧客マスタなど）には触らない。** イベント監視も、この2シートだけ。
- 画面で変更すると、変更したセルだけを書き込む。他の人が同時に変えた別のセルは上書きしない。
- Excelでこの2シートのセルを直接編集すると、ポップアップに反映される。

## 注意
- `index.html` を閉じる、または別のツールへ移動すると、ポップアップとの連携も終了する（ポップアップも閉じる）。使っている間は、`index.html` を開いたままにする。
- ブックは OneDrive／SharePoint に置く（共同編集のため）。
- このツールはExcelの外では動かない（ブラウザで `app.html` を直接開くと、ブラウザ内の保存だけで動く）。
- この環境にはExcelがないため、`Excel.run` を使う部分は実機では未確認。同期の仕組み自体は、疑似Excelに対するテストで確認済み。

## 実機での確認チェックリスト
1. メニューに「スケジュール」が出て、押すとポップアップが開き「Excel（計画シート）に接続しました」と出る。
2. ブックに `計画シート`・`計画マスタ` が作られ、既存シートに変化がない。
3. 画面で予定を追加すると1行増え、工数を変えるとその行の「入力値」だけが変わる。
4. 2人（または2つのウィンドウ）で開き、一方が `計画シート` のセルを書き換えると、もう一方のポップアップに反映される。
5. `wbs` シートの重い計算（数式）で、ポップアップの動きが遅くならない。

## 既存シートとの関係（今後の連携候補）
- `体制`（氏名・稼働開始日・稼働終了日）→ 要員
- `顧客マスタ`（顧客コード・取引先名・許容工数（人日/月））→ 取引先等、月ごとの許容工数
- `営業報告`（受託開始日・完了予定日・受託工数（人日）・担当者）→ 予定の元データ
- `wbs` には工数（人日）の列が無く、日別の値は進捗の色分け用の計算なので、今は連携していない。
