# 営業報告 Officeアドイン

Excelの「営業報告」シートを、タスクペインから **一覧／カンバン／集計** で操作できるアドインです。
新規入力はヘッダー右上の「＋新規入力」ボタンから行います（再読み込みボタンの左）。

**設定フラグ**: `app.js` 冒頭の `ENABLE_KANBAN_DND` を `true` にするとカンバンのドラッグ＆ドロップが有効になります（デフォルト `false`）。

## 画面構成

| 画面 | 機能 |
|---|---|
| 一覧 | 種別別グループ表示（**優先度列は左端**）。ワークフロー完了後の状態は「状態（m/d）」表示。状態フィルタは**複数選択可**。行クリック／右クリックで編集画面 |
| カンバン | 種別ごとのワークフローに沿った状態レーン（種別・状態フィルタは非表示）。DnDは `ENABLE_KANBAN_DND` フラグで制御（既定OFF） |
| 集計 | 保守状況／見積状況／受注状況／稼働状況 |
| ＋新規入力 | 起票情報のみ入力（対応状況は起票後に編集画面で入力） |

## 編集画面（ステージタブ式）

チケットの状態に応じたタブが活性化し、それ以外は 🔒 非活性になります。
**備考はタブの外にあり、どのステージでも編集できます。**

| タブ | 内容 | 完了時の遷移 |
|---|---|---|
| 起票 | 発生日・**起票者**・窓口・問合せ内容（新規入力時は担当者ではなく起票者を入力。担当者の初期値=起票者） | － |
| 対応中（保守・瑕疵・調整） | **対応担当者**（変更で担当者欄も更新）＋区分（保守対応のみ必須）＋対応状況 | 対応完了チェック→完了日を記録しチケット完了（開始日の右に完了日を表示） |
| 見積中（見積り） | **見積担当者**＋対応状況＋工数・価格（税抜）・**税込自動計算**・根拠 | 見積完了チェック→**見積完了日**を記録し確認中へ |
| 検討中（プリセールス） | **検討担当者**＋対応状況（検討・検証・提案作成など） | 検討完了チェック→**検討完了日**を記録し商談中へ |
| 商談中 | **窓口**＋商談状況 | 商談完了チェック→**商談完了日**を記録し確認中へ |
| 確認中 | 確認状況＋結果チェック | 「受注確定を完了にする」→**確認完了日**を記録・ステータスは確認中のまま受注タブ活性化／「失注」→確認完了日＋完了日を記録しチケット完了 |
| 受注 | 納品日・**計上日**・最終工数・最終価格（税込自動計算）・受注条件 | 完了チェック＋登録→ステータス「受注」・チケット完了 |

- 状態「新規」では対応状況欄は空のまま。**対応状況を記入して登録すると** 対応中／見積中／作成中へ遷移し、開始日（T列）を記録します。
- 完了したステージのタブは非活性となり、入力内容は参照のみ可能です。

## ワークフロー

- 保守対応・瑕疵対応・調整：`新規 → 対応中 → 完了`
- 見積り：`新規 → 見積中 → 確認中 → 受注 or 失注`
- プリセールス：`新規 → 検討中 → 商談中 → 確認中 → 受注 or 失注`
- どの状態からも「保留」に退避可能（カンバンDnD）

## 集計

- 集計期間は**期単位（10月〜翌9月、第37期=2025/10〜2026/09）**。◀▶ボタンで期を切り替えられます。
- **保守状況**: 保守対応＋瑕疵対応の月次推移を「発生」「完了」2系列のグラフで可視化。明細表に保守／瑕疵の内訳。
- **見積状況**: 見積り＋プリセールスを 新規→検討中→見積中→商談中→確認中→失注→受注 の順に件数・金額集計（受注は最終価格）。
- **受注状況**（旧: 売上予測）: 受注確定案件を**計上日ベース**で月別集計・グラフ化。計上日未入力の受注は警告表示。
- **稼働状況**: 期内の稼働キャパシティを可視化。サブタブは「全体キャパ／対応工数（保守）／受託工数」の3つ。
  - **全体キャパ**: 月次の基本稼働（営業日×体制シートの稼働人数）に対し、対応工数（保守）＋受託工数の合計がどれだけ溢れたかを積み上げ棒＋線グラフと月別内訳表で表示。
  - **対応工数（保守）**: 保守対応／瑕疵対応／調整の対応工数を、取引先ごとの**保守費（月額）・許容工数（人日/月）**と比較。表示は「月次／累計」を切替可能。分類チップ（すべて／保守／瑕疵／調整）で絞込み。見積り・プリセールスは受注確定前の工数を記録する列が現状の帳票に無いため対象外（受注後の工数は受託工数タブで扱う）。
  - **受託工数**: 取引先ごとの合計受注額・見積工数・実績（着手日〜納品日/完了日の日数比按分）を表示。行クリックで案件ごとの予実明細を下部に展開。
  - 基本稼働の算出には**体制シート**（稼働人数）と**祝日シート**（土日祝を除いた営業日数）を使用します。体制シートが未整備の場合は警告表示。
  - 「その他（社内業務・営業活動等）」の工数は現状未実装のため、実際の基本稼働との差はここに表示される値より小さくなる場合があります。

### 顧客マスタシート（無ければ自動作成）

A:顧客コード（英字2〜4文字） B:取引先名 C:窓口 D:備考 E:保守費（月額） F:許容工数（人日/月）
案件番号は「顧客コード-通番」（例: KM-01）で自動採番します。
E・Fは稼働状況「対応工数（保守）」の保守費比較に使用します（未入力の取引先は比較対象外）。
旧版（4列）のシートは起動時にヘッダーを自動でE・F列付きに書き直します（既存データは保持）。

### 体制シート（無ければ自動作成）

A:氏名 B:稼働開始日 C:稼働終了日
稼働状況の「基本稼働（人日）」計算に使う、月ごとの稼働人数の元データです。稼働終了日が空欄の人員は現在も稼働中として扱います。開始日・終了日と対象月の重なりで、月ごとの稼働人数をカウントします。

### 祝日シート（無ければ自動作成）

A:日付 B:名称
稼働状況の営業日数（8h/日ベースの基本稼働）算出時に、土日に加えてこのシートに登録された日付を非稼働日として除外します。

## デプロイ手順（GitHub Pages）

1. このフォルダ一式を `tools/addin/eigyo/` として GitHub Pages リポジトリに配置
2. `manifest.xml` をサイドロード、または Microsoft 365 管理センターから組織展開
3. Excelで対象ブックを開き、ホームタブの「営業報告」ボタンでタスクペインを表示

## デモモード

`index.html` をブラウザで直接開くと、Excelに接続せずサンプルデータで全機能を試せます（DEMOバッジ表示）。


## サイドメニュー（共通スライドメニュー）

ヘッダー左のハンバーカーボタン（≡）から、他アドインと共通のスライドメニューを開きます。
`tools/common/slide-menu.js` と `tools/common/menu.json` を遅延ロードして表示します。

- メニューには「操作（再読み込み）」と、共通の「ツール（カンバン → 営業報告 → バグ管理）」「リンク（使い方）」が並びます。
- カンバンの後ろに **営業報告**（id: `eigyo`）を追加した `menu.json` を同梱しています。共通ディレクトリ `tools/common/menu.json` をこの内容に差し替えてください（全アドインのメニューに一斉反映されます）。
- 現在表示中のアドイン（営業報告）はメニュー内で強調表示されます（`currentId: "eigyo"`）。

## この版の主な変更（rev_20260710_f）

### 詳細画面
- **削除ボタン**を追加。押下時に確認メッセージを表示し、OKで状態を「削除」に変更（一覧・カンバンから非表示になる）。

- 状態が「削除」の案件は表示しない（状態フィルタの選択肢からも除外）。
- **左クリック**で該当のExcel行に移動し、その行を選択状態にする。
- 一覧はクリックした行をハイライト（排他・単一選択）。
- 詳細画面を開くには**右クリック**または**ダブルクリック**。
- 確認中で受注を選んだ案件も、状態表示は「確認中」に統一（受注バッジを撤去）。

### 保守の対応中

- 一覧・カンバン共通で「先週実績」トグルボタンを追加。押すと**先週（月〜日）に更新されなかった案件を非表示にはせず、薄いグレー表示（opacity 0.4）**にする。もう一度押すと解除。
- 新規列 **AJ:最終更新日** を追加。案件の新規登録・ステージ編集・状態変更（保存操作）の都度、自動で当日の日付を記録する。「先週実績」判定はこの列を参照する。

## 稼働状況タブの追加（rev_20260820_c1e9d02）
- 集計に**稼働状況**タブを新設（受注状況の右）。サブタブ「全体キャパ／対応工数（保守）／受託工数」。期切替（◀▶）は他タブと同様。
- **全体キャパ**: 月次の基本稼働（営業日×要員数）に対する対応工数（保守）＋受託工数の積み上げ棒＋基本稼働の線グラフ、月別内訳表（営業日・要員数・基本稼働・対応工数・受託工数・合計・差分）。経過月中に溢れた月数・溢れ合計をKPI表示。
- **対応工数（保守）**: 保守対応／瑕疵対応／調整の対応工数を取引先ごとに集計し、顧客マスタの保守費（月額）・許容工数（人日/月）と比較。表示切替は**「月次」「累計」**（旧案A/案Cの案から名称変更）。分類チップ（すべて／保守／瑕疵／調整）で絞込み可能。取引先ごとに月次バー（許容超過は赤）または累計バーと、超過回数・保守費乖離額を表示。
- **受託工数**: 見積り／プリセールスの受注後案件（受託中・完了）を対象に、取引先ごとの合計受注額・見積工数（Y列:最終工数）・実績工数（AN列:受託工数、着手日〜完了予定日/完了日の日数比按分）を集計。行クリックで案件別の予実明細（見積工数・実績工数・消化率・見積残・金額・状態）を下部に展開。
- **新規シート**: **体制**（氏名・稼働開始日・稼働終了日）で月次の稼働要員数を管理。**祝日**（日付・名称）で土日以外の非稼働日を管理し、基本稼働（8h/日換算の営業日数×要員数）の算出に使用。どちらも未作成の場合はヘッダー付きで自動作成し、体制シートが空の場合は稼働状況タブに警告を表示。
- **顧客マスタシートに列を追加**: E:保守費（月額） F:許容工数（人日/月）。既存4列シートは起動時に自動でヘッダーを拡張（データは保持）。
- 「その他（社内業務・営業活動等）」の工数管理は仕組みが未整理のため今回は対象外。実際の基本稼働との差は、その分だけ本タブの表示値より小さくなる場合があります。

## 稼働状況タブの改修（rev_20260821_d4a2f19）
- **対応工数（保守）の分類フィルタを拡張**: 「見積り」「プリセールス」を瑕疵と調整の間に追加（すべて／保守／瑕疵／見積り／プリセールス／調整）。見積り・プリセールスも他の種別と同じ対応工数（AM列）を集計対象とし、対象は受注確定前の段階（新規・見積中・検討中・確認中など）まで（受注・受託中・完了になった案件は「受託工数」タブ側でカウントするため、二重計上を避けるためここでは対象外）。
- **分類フィルタに複数選択トグルを追加**: OFF（既定）は従来どおり単一選択、ONにすると保守・瑕疵など複数の分類を組み合わせて絞り込めます。
- **保守費・許容工数が未設定の取引先も表示**: 従来は一覧から除外し件数のみ注記していたが、「保守費 未設定の取引先」欄を新設し実績（人日）のみを表示するようにした（乖離は算出しない）。
- **保守費乖離を独立列に**: 各取引先行の右端に「保守費乖離」列を配置（従来はバッジ下に縦積み表示）。
- **KPIの並び順を変更**: 「保守費との乖離／実績・許容／超過している取引先／保守費設定済み取引先」の順に変更。
- **受託工数に状態フィルタを追加**: すべて／受託中／完了で絞り込み可能に（従来は常に受託中・完了を合算）。
- **受託工数のKPIラベルを変更**: 「見積 / 実績 工数（人日）」→「実績 / 見積 工数（人日）」（値の並びも実績を先に統一）。
- **全体キャパ／対応工数（保守）／受託工数の切替をタブ形式に変更**: ボタンからタブ（下線スタイル）に変更し、期セレクタとあわせて画面上部に固定表示（スクロールしても常に見える）。
- 全体キャパの「対応工数（保守）」集計対象は従来どおり保守対応・瑕疵対応・調整の3種のみに固定（分類フィルタの拡張とは独立）。

## 対応工数（保守）／受託工数の集計元カラムを修正（rev_20260821_e7c0b3d）
- **対応工数（保守）に見積り／プリセールスを含める場合の集計元をAM列（対応工数）に統一**: 従来案のK列（見積工数）ベースから変更。見積り・プリセールスの各ステージで入力する対応工数（人日）をそのまま集計します。
- **受託工数タブの「見積」をY列（最終工数）ベースに修正**: 従来AM列（対応工数）を流用していたが、受注確定時に入力するY列（最終工数）が正しい見積基準のため変更。取引先集計・見積超過判定・KPI・案件別明細（消化率・見積残）・全体キャパの受託工数按分（受託中ステータス分）すべてに適用。

## 対応工数（保守）の状態フィルタを撤廃（rev_20260821_f2b9a41）
- 対応工数（保守）に見積り／プリセールスを含める場合、当初は「受注・受託中・完了になった案件は対象外（受託工数タブと二重計上しないため）」としていたが、**状態を問わずAM列（対応工数）を計上する**よう変更（保守対応/瑕疵対応/調整と同じ扱いに統一）。
- そのため、受注確定後の案件は「対応工数（保守）」（AM列）と「受託工数」（Y列・AN列）の両方に数字が出る場合がある。列としては別の値だが、同じ案件の工数が両タブに現れる点は把握のうえ利用すること。

## 集計タブのサブタブ・稼働状況ヘッダーを固定表示に（rev_20260821_a8c7e52）
- 集計画面のサブタブ（保守状況／見積状況／受注状況／稼働状況）を `position: sticky` で固定し、下のコンテンツをスクロールしてもサブタブが常に見える状態に変更。
- 稼働状況タブでは、サブタブの直下に期セレクタ＋ビュータブ（全体キャパ／対応工数（保守）／受託工数）が重ならず連続して固定表示されるよう、両者の固定オフセットを調整（サブタブの高さ＋余白ぶんを稼働状況側のオフセットに反映）。
- 一覧／カンバン／スケジュール／集計の画面切替タブは元々スクロール領域の外にあり、対象外（従来から固定表示）。
- Playwrightでの実スクロール確認済み：稼働状況タブ（全体キャパ／対応工数（保守）／受託工数の3ビューすべて）に加え、保守状況／見積状況／受注状況の他3サブタブでも `.agg-seg` が正しく固定され、画面崩れ・エラーがないことを確認。
